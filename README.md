# Disable oEmbed Endpoint (Security)

Отключает oEmbed в WordPress: REST-маршруты, discovery-ссылки, скрипт
`wp-embed.js`, провайдеров и шаблон `/embed/`. Нужен там, где oEmbed
используется как прокси: `/wp-json/oembed/1.0/proxy` заставляет сервер
ходить по произвольному URL (SSRF, обход блокировок, слежка за посетителями
через сторонние домены).

Версия 1.2.0. Требуется WordPress 7.0+, PHP 8.4+.

## Что отключается

| Что | Как |
|---|---|
| `GET /wp-json/oembed/1.0/embed` | маршрут не регистрируется и вырезается из карты эндпоинтов |
| `GET /wp-json/oembed/1.0/proxy` | то же — основная точка SSRF |
| `<link rel="alternate" type="application/json+oembed">` | убран из `<head>` |
| `wp-embed.js` | не подключается |
| Провайдеры oEmbed | список пуст, `wp_oembed_get()` возвращает `false`, в контенте остаётся обычная ссылка |
| Обнаружение провайдеров для неизвестных URL | `embed_oembed_discover` выключен |
| `/{запись}/embed/` | отвечает 404 |

Встраивание видео с YouTube и подобных сервисов после активации
превращается в ссылку — это ожидаемое поведение, а не ошибка.

## Установка

1. Скопировать каталог `disable-oembed-security` в `wp-content/plugins/`.
2. Активировать плагин в разделе «Плагины».

Настроек нет: плагин только отключает, ничего не добавляет в базу.

## Отключение блокировки шаблона

Если `/embed/` нужен, шаблон можно вернуть фильтром в теме или mu-plugin:

```php
add_filter( 'doe_block_embed_template', '__return_false' );
```

REST-маршруты при этом остаются отключёнными.

## Обновления

Плагин обновляется штатным механизмом WordPress из репозитория
[Gnoztis/disable-oembed-security](https://github.com/Gnoztis/disable-oembed-security):
берётся релиз или тег вида `vX.Y.Z`, архив — zipball GitHub. Проверка
кэшируется на 6 часов, кнопка «Проверить обновления» в строке плагина
сбрасывает кэш.
