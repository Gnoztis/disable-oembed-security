# Disable oEmbed Endpoint (Security)

Отключает oEmbed в WordPress: REST-маршруты, discovery-ссылки, скрипт
`wp-embed.js`, провайдеров и шаблон `/embed/`. Нужен там, где oEmbed
используется как прокси: `/wp-json/oembed/1.0/proxy` заставляет сервер
ходить по произвольному URL (SSRF, обход блокировок, слежка за посетителями
через сторонние домены).

Версия 1.3.11. Требуется WordPress 7.0+, PHP 8.0+.

## Что отключается

| Что | Как |
|---|---|
| `GET /wp-json/oembed/1.0/embed` | маршрут не регистрируется и вырезается из карты эндпоинтов |
| `GET /wp-json/oembed/1.0/proxy` | то же — основная точка SSRF |
| `<link rel="alternate" type="application/json+oembed">` | убран из `<head>` |
| `wp-embed.js` | не подключается |
| Провайдеры oEmbed | список пуст, `wp_oembed_get()` возвращает `false`, в контенте остаётся обычная ссылка |
| Запросы к внешним oEmbed-провайдерам | не выполняются: проверка останавливается до HTTP-запроса |
| Обнаружение провайдеров для неизвестных URL | `embed_oembed_discover` выключен |
| `/{запись}/embed/` | отвечает 404 |

Встраивание записей этого же сайта продолжает работать: WordPress
собирает такое встраивание из локальной записи и не делает ни одного
внешнего запроса. Встраивание видео с YouTube и подобных сервисов после
активации превращается в ссылку — это ожидаемое поведение, а не ошибка.

## Установка

1. Скопировать каталог `disable-oembed-security` в `wp-content/plugins/`.
2. Активировать плагин в разделе «Плагины».

Настроек нет: плагин только отключает, ничего не добавляет в базу.

## Если нужны встраивания

Плагин можно ослабить точечно, фильтрами в теме или mu-plugin.

Вернуть шаблон `/embed/`:

```php
add_filter( 'doe_block_embed_template', '__return_false' );
```

Разрешить внешние oEmbed-запросы (вместе с обнаружением провайдеров):

```php
add_filter( 'doe_block_oembed_result', '__return_false' );
```

REST-маршруты `/oembed/1.0/embed` и `/oembed/1.0/proxy` при этом остаются
отключёнными: вернуть их фильтром нельзя.

## Обновления

Плагин обновляется штатным механизмом WordPress из репозитория
[Gnoztis/disable-oembed-security](https://github.com/Gnoztis/disable-oembed-security):
берётся последний релиз, а если релиза нет — тег вида `X.Y.Z` (префикс `v`
тоже принимается). Пакет — zip-ассет релиза, если он приложен, иначе архив
zipball GitHub.

Проверка кэшируется на 6 часов, неудачная повторяется через 15 минут.
Кнопка «Проверить обновления» в строке плагина на странице «Плагины»
сбрасывает кэш и запускает проверку заново.

### Токен GitHub (необязательно)

Анонимные запросы к GitHub API ограничены 60 в час на IP хостинга. Если на
одном IP несколько сайтов и плагинов, лимит исчерпывается, и вместо обновлений
в строке плагина появляется «проверка не удалась: 403 (лимит GitHub API)».
Собственный токен поднимает лимит до 5000 запросов в час.

Задайте константу в `wp-config.php` — или тем же значением через фильтр
`doe_github_token` в mu-plugin:

```php
define( 'DOE_GITHUB_TOKEN', 'github_pat_...' );
```

Подойдёт fine-grained token с правом **Contents: Read** на репозиторий плагина
(для публичного репозитория прав на запись не нужно). Без константы плагин
работает как обычно, просто с общим лимитом; токен нигде не выводится и
передаётся только хостам `github.com` и `api.github.com`.
